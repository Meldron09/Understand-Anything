# Two video renderers, silent clips, and shared narration and assembly

The video skill ships two renderers in v1: Manim Community Edition (tier 2, Python via `uv` plus cairo, pkg-config and ffmpeg) for math, geometry, simple 3D and algorithm traces, and HyperFrames (tier 3, Node 22+ and Chromium, pinned to an exact version, telemetry off, frame streaming on) for processes, diagrams, definitions, data charts and code walkthroughs. `shared/renderers.md` has five rows (concept type, pick, fallback, tier, ref). A fallback is never a higher tier than its pick, so HyperFrames rows fall back to Manim and Manim rows have none. A unit uses one renderer and the router takes the dominant row. Revideo, handanim and Blender are deferred, and VHS gets no row (a terminal concept is a styled block in a HyperFrames scene).

A renderer only produces a silent 1280x720, 30 fps clip per scene. Narration, captions and assembly are shared, audio-first steps: the subagent writes a `storyboard.md` (one idea per scene, about 45 words of narration, one fixed voice), synthesizes every scene in one `uv` process with kokoro-onnx (fallback `say`), measures each wav, bakes that duration D into the scene script, renders the clips, and the assembler trims or holds each clip to D, concatenates, and writes sentence-level SRT from the measured durations (soft `mov_text` track when the probe allows, no burn-in). A unit's scene count is `round(size_seconds / 20)`, minimum 2, with the real length within 25% of `size` (re-synthesized once before rendering if not). Each renderer has one `refs/<renderer>.md` of about 120 lines (fit, install and probes, headless flag, scene script format, render command, pitfalls, unknowns pending a Mac spike), and one style block in `SKILL.md` keeps the two renderers visually coherent.

Failure is per scene inside the unit subagent. A scene that fails to render is rewritten once with the row's fallback renderer, then becomes a blank scene (flat clip, audio and caption intact, recorded `degraded: sNN blank`). More than half the scenes blank, or the smoke render of the first scene failing on both renderers, returns `status: failed` and the conductor re-dispatches once to text (ADR 0003). Missing TTS goes to `say`, then to silent video with estimated durations (2.5 words per second) and a narration script file. Missing ffmpeg fails the unit at once to text. The numbers (20 s scenes, the blank-scene threshold) are untested defaults to retune after a Mac spike.

Rejected: shipping all five researched renderers (a reference file, a spike and a pin each, and three toolchains instead of two), Revideo beside HyperFrames (a second Node renderer for animated code diffs alone), renderer-native audio and captions (two narration paths, a HyperFrames sign-in preflight, and a fallback renderer would redo audio), per-unit renderer fallback (rewrites every scene to save one), and dropping a failed scene silently (the learner would miss content). This supersedes the research picks for animated diagrams, code walkthroughs, data animation, whiteboard, slides-to-video and 3D, and the final spec must reconcile ADR 0001: tier 2 needs a cairo and pkg-config probe, and tier 3 names Node and Chromium only, not Blender.

# Conductor with hidden step skills, and the lesson plan on disk as the only seam

One user-invocable skill, the conductor (`/learn-anything:learn`), runs in the main thread and sequences intake, ingest, the router, the mode skills and the comprehension check, holding only paths and unit statuses. Every other skill (intake, ingest, router, each mode skill, the video mode skill) is `user-invocable: false`, which keeps it routable by the conductor. Their descriptions say they are internal steps and state whether they run inline or spawn subagents. Mode skills are conductor-only in v1: a "just make flashcards" request goes through the conductor and a short intake.

The router reads the learner brief and the source doc's chunk index, never the full source text, and writes the lesson plan to `./learn-anything/<lesson-slug>/plan.md`: a list of lesson units, each with an id, mode, a list of source slices (possibly from several sources), renderer for video units, and a `status` (`pending`, `done`, `degraded: <reason>`). The conductor dispatches one unit at a time by id, and a mode skill reads the brief, its unit and its slice from disk by path, so whether a unit runs inline or in a subagent is invisible to the plan. The learner's mode choice is binding: the router chooses slicing, order and renderers and sizes the plan to the time budget (interactive units at 5 minutes per widget), but never adds or drops a mode. The conductor shows the plan once for confirm or adjust before any rendering, skipping the gate when the plan is exactly one tier-0 unit, and on start resumes this lesson's unfinished units from `plan.md`.

Renderers are reference files under the one `video` skill, not skills. The router picks the renderer at plan time from a single compact table (concept type, pick, fallback, tier) kept in `shared/renderers.md`, maintained with the video skill and read by the router (anything read by two or more skills lives in `shared/` or `scripts/`), because ADR 0001 requires predicting failures at plan time; the video skill follows the pick and applies the fallback chain at render time.

Rejected: a single skill with every mode as a reference file (no per-mode descriptions to test, and the mode skill term disappears), several user-invocable step commands (hands sequencing to the learner), one skill per renderer (crowds the skill listing budget), standalone-triggerable mode skills (a second input path and description collisions with other plugins), and letting the video skill pick the renderer at execution time (the plan gate and plan-time prediction could not show it).

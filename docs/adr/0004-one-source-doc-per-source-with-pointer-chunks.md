# One source doc per source, pointer chunks for PDFs, and conductor-run two-phase ingest

Ingest writes one source doc per source to `./learn-anything/<lesson-slug>/sources/<source-id>/index.md` (ids `s1`, `s2`, in the order the learner gave them), never a merged one. The index holds YAML frontmatter (kind, origin, hash, fetch time, `grounded`, token total, chunking rung, status) and one entry per chunk: `id` (`c01`), title, origin (heading path or pages), token estimate, an optional path to the chunk's text, and a one-line summary of at most about 25 words. A slice is written `s2#c03-c05`, and a lesson unit may list slices from several sources, so the router reads each source's index and no combined manifest exists.

A PDF chunk always records its page range, and also gets a `pdftotext -layout` text cache when the PDF has a text layer; a scanned PDF gets the page pointer only. Mode skills read the cache by default and read the pages natively when a slice needs figures or equations. Original files are referenced in place and hashed, not copied; a moved file makes that source `failed` on resume. A URL is one page fetched to disk with `curl` and converted by a `uv run` script, so its size is known before any content enters the main thread, and it is not re-fetched unless the learner asks. A bare topic becomes a one-chunk source doc with `kind: topic` and `grounded: false`: ingest does no research for it.

Large sources are ingested in two phases run by the conductor, because subagents spawn none (ADR 0003): one source subagent cuts the source and writes the chunks and an index without summaries, then the conductor spawns `haiku` batches of about 5 chunks, each writing its summaries under `work/`, and a script merges them into `index.md`. No agent writes an index concurrently. Small sources run inline in the main thread, which writes the summaries itself. If some sources fail the lesson continues without them and the plan gate lists the failures; if every source the learner gave fails, ingest stops and says so, and never falls back to an ungrounded topic.

Rejected: a merged source doc (needs a cross-source ordering and dedup step nothing else needs), extracted text only for PDFs (flattens equations, tables and charts, the one thing native page reading preserves), copying originals into the lesson folder (duplicates large files), one subagent doing cuts and all summaries (serial, and loses the `haiku` batching), a crawl for URLs (unbounded size, robots handling, can blow the inline threshold unnoticed), and researching a bare topic during ingest (a second research feature with a citation burden nobody asked for).

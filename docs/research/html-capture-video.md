# Research: HTML/CSS animation capture video (issue #22)

Date of research: 2026-10-24. Question: how well does HTML/CSS/GSAP-capture video (HyperFrames; and the generic headless-browser + ffmpeg approach) fit learn-anything? Free/OSS and local only.

Nothing was installed or run. Every "sample quality" statement is **not verified locally**; it rests on the project's own showcase. "Unknown" means the primary sources read did not say. Sources are the repos, their docs, license files and the GitHub/npm APIs, not blogs. Repo files cited as `heygen-com/hyperframes@main:<path>` are at https://github.com/heygen-com/hyperframes/blob/main/<path>.

## Pick and fallback (summary)

- **Pick: HyperFrames** (Apache-2.0), used as a *renderer* behind a mode skill, with the free local path pinned (Kokoro TTS and local Whisper, CSS/WAAPI or GSAP, telemetry off). Pin an exact version.
- **Fallback: a thin in-house seek-and-screenshot loop** (Playwright or Puppeteer + ffmpeg) over HTML authored to a seekable contract. This is my design sketch, **not verified**. Degrade-to-baseline: real-time Playwright `recordVideo` of the interactive HTML.
- Not a general explainer renderer for math: equation-heavy content stays with the math-animation pick.

## A. HyperFrames notes

- **What it is:** "Write HTML. Render video. Built for agents." Compositions are plain HTML with `data-start` / `data-duration` attributes; a paused timeline is seeked frame by frame in headless Chrome and encoded with FFmpeg (README; `docs/concepts/determinism.mdx`). Adapters exist for GSAP, CSS, WAAPI, Lottie, Three.js, Anime.js (README; `docs/concepts/frame-adapters.mdx`). Output: MP4, WebM, MOV, GIF, PNG sequence, HLS (`docs/packages/cli.mdx`, `render`).
- **Authoring contract (matters for us):** no `Date.now()`, unseeded `Math.random()`, network fetches, timers or `repeat: -1`; everything visible is a function of timeline time; a new video is 1920x1080 at 30 fps; a root `index.html` mounts one scene per sub-composition (`skills/hyperframes/SKILL.md`). `hyperframes check --json` lints violations. This gives per-scene units that map well onto a lesson plan's scenes.
- **Claude Code fit:** ships a Claude Code marketplace plugin and seven skills (README; `.claude-plugin/marketplace.json`). The entry skill `/hyperframes:hyperframes` can run the whole job from a topic or notes (README; `docs/guides/faceless-explainer.mdx`). For learn-anything the question is whether to depend on the vendor's skills or write our own mode skill that only calls the CLI. Plugin-to-plugin dependencies are the only kind (ticket #14), so a dependency would be on the whole `hyperframes` plugin; not decided here.
- **Narration/captions:** local TTS is Kokoro (`npx hyperframes tts`, Apache-2.0 model per https://github.com/hexgrad/kokoro); local Kokoro returns **no word timestamps** (`skills/media-use/audio/references/tts.md`), so captions need a separate transcribe pass: `hyperframes transcribe` uses Parakeet if installed, else Whisper (`docs/guides/voice-and-audio.mdx`). There is a captions block in the registry (about 450 blocks per README). The skill's Preflight stops to ask the user to sign in to HeyGen or continue offline with Kokoro; our mode skill must pre-answer that. The narration/captions ticket should decide whether HyperFrames' pipeline is reused or replaced.
- **Interactive-HTML overlap:** HyperFrames' own slideshow is a live deck, not video, and "cannot be exported as one linear MP4 yet"; `render` on a deck silently renders only the first slide (`docs/guides/slideshow.mdx`). Shared with the interactive mode (ticket #15 pick: vanilla JS + inline SVG/CSS): SVG/CSS authoring skills and brand/design tokens. Not shareable as-is: an interactive lesson artifact relies on event handlers and free-running animation, which the determinism contract forbids, so a video scene must be a separate seekable composition. Whether one SVG diagram source can feed both is unknown; needs a spike.
- **Telemetry and "local only":** telemetry (command names, render performance, OS/CPU/memory, sandbox runtime, the coding-agent name such as `claude_code`) is **on by default**; opt out with `HYPERFRAMES_NO_TELEMETRY=1`, `DO_NOT_TRACK=1` or `hyperframes telemetry disable`. Opting out also removes the install from canary rollouts (`docs/packages/cli.mdx`, `telemetry`). A marketplace plugin should document this and set the env var.
- **GSAP:** the README says GSAP is "100% FREE including ALL bonus plugins ... even for commercial use" under GreenSock's standard "no charge" license (https://github.com/greensock/GSAP README). I could not read the full license text (the page fetched did not include terms), so restrictions are **unknown**. It is avoidable: CSS and WAAPI are supported adapters, but the default examples and skills use GSAP and load it from a CDN in at least some examples (`CREDITS.md`). A no-network render would need it vendored locally: unverified.
- **Risks:** pre-1.0 and daily releases; macOS capture is the slower screenshot path and is the user's primary platform; frames spill to disk on that path; `--low-memory-mode` engages automatically at 8 GB RAM or less (one worker); parallel workers are not bit-identical, `--workers 1` for exactness (`docs/prompting/rules-and-anti-patterns.mdx`, per the sweep; not re-read here). Frame-exact reproducibility across machines needs Docker (`docs/concepts/determinism.mdx`), which we do not need for lessons.

## B. DIY seek-and-screenshot notes

- **timecut** (BSD-3, last push 2023-07-18): overrides JS time functions and screenshots frames into ffmpeg; its README says pages animating via CSS transitions/animations "will likely not render as intended" (https://github.com/tungs/timecut). Stale and not viable.
- **puppeteer-capture** (MIT, pushed 2026-10-17, 22 stars): uses Chrome `HeadlessExperimental.beginFrame`; README comparison table says platform "Linux, Windows" (https://github.com/alexey-pelykh/puppeteer-capture). Not macOS, so not a fit for the primary target. (HyperFrames itself uses BeginFrame only on Linux `chrome-headless-shell` and falls back to screenshots on macOS: CLI docs.)
- **Own loop:** page.screenshot per frame after seeking, pipe to ffmpeg. This is essentially what HyperFrames' engine does plus audio mix, fonts, readiness gates and workers. Reinventing it is cost with no upside unless HyperFrames proves unusable on a Mac. How to seek CSS/WAAPI animations deterministically (`document.getAnimations()` and `currentTime`) is a standard web API, but I did not verify it here.

## C. Real-time recording notes

Playwright `recordVideo` writes on context close, defaults to viewport scaled into 800x800, and the doc states no frame rate or determinism (https://playwright.dev/docs/videos). Puppeteer's screencast is documented as real-time WebM (sweep source, https://pptr.dev/api/puppeteer.page.screencast, not re-read here). Useful only as a zero-authoring degrade path for an existing interactive artifact.

## Best-fit concept types for HyperFrames

Good: process and mechanism explanations (pipelines, request lifecycles, state changes), kinetic-type definitions and key-point recaps, diagram reveals, data and chart stories, code-diff or PR walkthroughs, "docs to video". Weak: equation derivations (math-animation ticket's pick), hand-drawn whiteboard style (whiteboard ticket's pick), long-form talking-head content. These tiers are my reading of the vendor's guides, not tested.

## Pick and Fallback

**Pick: HyperFrames.** It is the only candidate that is maintained, macOS-capable, CLI-headless, Apache-2.0, and already contains the pieces learn-anything needs (seekable HTML contract, per-scene sub-compositions, local TTS, local transcription, captions, a Claude Code plugin). It lets the model write HTML/SVG/CSS, which matches the interactive-HTML authoring skills. Conditions: pin an exact version; set telemetry off; pre-answer the HeyGen sign-in preflight; document Node 22+, FFmpeg and a one-time Chrome download as dependencies; fall back to text if the dependency check fails. Spec must mark render time on macOS as unmeasured until the spike.

**Fallback: DIY seek-and-screenshot** (Playwright or Puppeteer + ffmpeg), on HTML authored to the same seekable contract, only if HyperFrames is abandoned, breaks the plugin, or fails the sandbox flag. Reasons: same free dependencies, no vendor coupling, small. Cost: we own audio mixing, readiness and workers. puppeteer-capture does not support macOS and timecut is stale, so neither is the fallback. Lowest-tier degrade: real-time Playwright recording of the interactive artifact.
